# 戦略ブリーフ（レポートの型）

社内の戦略整理ブリーフ（v11、2026/11）の構造と工夫を型にしたもの。
見た目は `template.html` をそのまま使い、中身だけを差し替える。

## 1. まず決めること（書き始める前に）

| 決めること | 例 |
|---|---|
| 読み手 | 社内の相談相手、経営会議、相手企業 |
| 読み手にしてほしいこと | レビューしてほしい／決めてほしい／動いてほしい |
| この資料で決めたいこと（1〜3個） | 目的の主従、最初の一手、投資の可否 |
| 末尾の章の型（下表） | 相談型 |
| 配布範囲 | 社外秘／チーム内／社外提出可 |

末尾の章は、目的に合わせて差し替える。第1〜3章の構造は共通。

| 型 | 第4章の名前 | 第4章の中身 |
|---|---|---|
| 相談型（見本） | ○○さんに相談したいこと | 論点カード：伺いたいこと／背景／AIの仮の答え／答えで変わること |
| 確認型 | 次回MTG・現地で確かめたいこと | 論点カード：聞きたいこと／背景／仮の答え／答えで変わること |
| 意思決定型 | 決めていただきたいこと | 決裁カード：決めること／選択肢／推奨／決めないと何が止まるか／期限 |
| 提案型（社外向け） | ご提案と進め方 | 相手のメリット、役割分担、段階と判断点。AIの見立てタグは外す |

## 2. 材料の集め方

- Notionのページは `notion-fetch` で読む。大きいページは結果がファイルに保存されるので、`jq -r .text` で本文を取り出し、表を圧縮してから読む。
- ページに添付・埋め込みされたファイル（`notion-file-block://...`）は `notion-get-file-download-urls` で署名付きURLを取り、`curl` で保存してから読む（URLは数分で切れる）。
- URLのアンカー（`#xxxx...`）はブロックIDを指す。本文中で `xxxxxxxx-xxxx-...` のようにハイフン付きで探す。リンク先が埋め込みファイルのことがある。
- 外部サイトがボット対策で読めないときは、回避しない。チームの確認内容を「チームの見立て」として使い、出典欄に「直接は読めていない」と書く。
- 材料は全部読む。読めなかったもの（添付のExcelなど）は第2章の「評価の材料と限界」に必ず書く。

## 3. 構造

```
表紙        コード行（STRATEGY BRIEF — 日付 版）／タイトル／サブタイトル（目的を一文）／メタ（作成・更新、作成者と整理者、元資料、配布範囲）
導入        リード文（何の事業で、いま何の段階で、何のためにこの資料があるか）
            タグの凡例（事実／チームの仮説／AIの見立て／未確認）
            ★この資料で決めたいこと（濃紺カード、1〜3個）
            ★前回からの変更（版を重ねたときだけ）
            結論カード4枚（01〜04。各カードは太字の一文＋3〜4文の根拠）
第1章 現状整理    事実だけ。評価は書かない。8〜13節
            定番の節：事業とプロダクト／ここまでの経緯（時系列表）／お金（価格・計画）／売り方／競合・先行者
                      ／ヒアリングで分かったこと／決まったこと・決まっていないこと（2列）
第2章 AIの評価    2-1 評価の材料と限界（必ず最初）
            2-2 結論（濃紺カード。見出しは結論の一文そのもの）
            2-3〜 論点ごとの評価（1節1論点。見出しは問いか主張）
            最後 評価の一覧（○△×の表）
第3章 あるべき仮説 3-1 仮説を一文で（青線カード）
            3-2 N個の仮説と確かめ方（表：仮説／確かめ方／外れたら／★担当・期限）
            3-3〜 数字で見た成立条件、道の選び方、範囲、入り方
            最後 次の一手（番号付きリスト）
第4章 （型による）  論点カード Q1〜。優先度バッジ（最優先／次に）。最後に「問い返されそうなこと」か「次回のアジェンダ案」
付録 A      A-1 出典（★番号付き S1, S2...）／A-2 用語
```

★は、見本から改善して加えた要素（6章）。

## 4. 書き方のルール

**事実と意見を分ける**
- 章で分け（第1章＝事実、第2章＝評価、第3章＝仮説）、さらに段落ごとにタグを付ける。
  - `tag f` 事実：資料・公開情報・データで確認できること
  - `tag h` チームの仮説（見立て）：計画や会話にあるが、まだ確かめていないこと
  - `tag v` AIの見立て：AIが資料から読んだ評価と提案
  - `tag u` 未確認：確かめる予定のこと、読めなかった資料に基づくこと
- 見本の比率は、事実41：チーム9：AI17。事実が一番多い状態を保つ。

**読み手が反応しやすくする**
- 論点カードには必ず「仮の答え」を書く。白紙で問わない。
- 「答えで変わること」を書き、その論点を議論する意味を示す。
- 優先度は2段（最優先／次に）まで。

**根拠と限界**
- 節の終わりに出典（`p.src`）を付ける。数字の計算方法、換算レート、時点も書く。
- 根拠のない数字は「置き値」「推計」「未検証」と明記する。確度が低い出典は「確度は中〜低」と書く。

**文体**
- です・ます。短い平叙文。1文に1つのこと。
- 主語と数字を具体的に書く（「多い」ではなく「1,050万超」）。
- 専門用語は付録の用語集に入れ、本文では言い換える。
- 人名は資料の表記に合わせ「○○さん」。

**数字と図**
- 主要な数字は `tiles`（5枚まで）。規模の比較は `bars`。損益や収支は濃淡の表（`td.h n2/n1/z/p1/p2`、数字は必ず表示）。評価は `mk ok/mid/ng`。
- 図（`fig` + インラインSVG）は、一番伝えたい論点に1〜2枚だけ使う。`aria-label` に図の結論を一文で書く。

**参照**
- 節番号（1-1、2-3）を振り、本文から「（2-7）」と相互参照する。目次（左の固定ナビ）と見出しのIDを一致させる。

## 5. コンポーネント（template.html のクラス）

| 用途 | クラス |
|---|---|
| 章の見出し | `section.ch` > `.chhead` > `.code`（● 01 — CURRENT STATE）+ `h2` |
| 節の見出し | `h3` > `span.no`（1-1）+ 見出し |
| リード文 | `p.lead` |
| 結論カード | `.concl` > `.c` > `.n` + `p`（先頭を `b` で一文） |
| 強調カード | `.card.key`（青線）、`.card.dark`（濃紺、結論用） |
| 数字タイル | `.tiles` > `.tile` > `.l` / `.v`（`small` で単位）/ `.d` |
| 横棒 | `.bars` > `.ttl` + `.bar(.em/.sub)` > `.lab` / `.trk i[style=width]` / `.val` |
| 表 | `.tblwrap` > `table(.tight/.brk)`。強調行は `tr.hl` |
| 評価マーク | `span.mk.ok/.mid/.ng` > `i`（◎○△×?） |
| 論点カード | `.q` > `.qh`（`.n` `.t` `.pri`／`.pri.b`）+ `.qb` > `dl`（`dt`/`dd`、問いは `dd.ask`） |
| 2列 | `.two` |
| 出典 | `p.src`、小さい注記は `.small` |
| ★確度 | `span.conf.hi/.md/.lo` |
| ★出典番号 | `sup.cite > a[href=#S1]` と付録の `li id="S1"` |
| ★変更履歴 | `.card.chg` |

## 6. 見本から改善した点（このテンプレートに組み込み済み）

1. **この資料で決めたいこと**を表紙の直後に置く。結論カードの前に、読み手の役割を伝える。
2. **未確認タグ（`tag u`）**を加える。読めなかった資料、現地で確かめる予定のことを区別する。
3. **前回からの変更**カードを置く（v2以降）。何が変わり、どの結論・仮説に効いたかを3〜5行で。
4. **仮説表に「担当・期限」**の列を足す。確かめ方が行動に変わる。
5. **出典に番号**（S1…）を振り、本文から引けるようにする。
6. **確度ラベル**（高・中・低）を、推計や二次情報の数字に付ける。
7. **末尾の章を目的で差し替える**（1章の表）。同じ型で、相談・確認・決裁・提案に使える。

## 7. 仕上げのチェックリスト

- [ ] 結論カードだけ読んで、何が問題で、何をすべきかが分かる
- [ ] 第1章に評価や提案が混ざっていない
- [ ] すべての論点カードに仮の答えと「答えで変わること」がある
- [ ] 推計・置き値・未確認が明記されている。読めなかった資料が2-1にある
- [ ] 数字に時点・単位・出典がある。換算レートが書いてある
- [ ] 目次のリンクと見出しIDが一致し、相互参照の番号がずれていない（節を足したら振り直す）
- [ ] 1280px と 390px で横スクロールが出ない（Playwrightで確認）
- [ ] 版と日付を表紙・フッターの両方で更新した

## 8. 保存と共有

- 社外秘の中身を含むブリーフは、公開リポジトリにコミットしない。作業用フォルダに置いてユーザーに送り、Notionの元ページへの添付を提案する。
- ファイル名：`<テーマ>_<内容>_<YYYYMMDD>_v<版>.html`。
- 更新するときは前の版を残し、「前回からの変更」を書く。
