# レポートの型の選び方と作り方

内容と目的に合わせて型を選び、共通のデザインと部品で1ファイルのHTMLにする。
戦略ブリーフの書き方の細かいルールは `../strategy-brief/SKILL.md` にある。どの型でも、そこの「書き方のルール」（事実と意見を分ける、出典、文体）を守る。

## 1. 型を選ぶ

### 手順
1. 材料を全部読む（読み方は strategy-brief の「材料の集め方」）。
2. 次の4つを、依頼文と材料から判断する。分からなければ既定値を使う。

| 問い | 選択肢 | 既定値 |
|---|---|---|
| 読み手に何をしてほしいか | レビュー・助言／判断・決裁／構想を固める／記録・共有／現地で聞く／検証結果を学ぶ／進捗を追う | レビュー・助言 |
| 段階 | 探索／構想／検証／実行 | 探索 |
| 読み手 | 社内の有識者／経営／チーム／相手企業・社外 | 社内の有識者 |
| 材料の中心 | 会議の記録／調査・公開情報／数字・計画／決定事項 | — |

3. 下の表で型を決める。最初の返答で「この内容なので○○型で作ります（理由を一文）」と伝える。
4. 2つの型で迷い、出来上がりが大きく変わる場合だけ、ユーザーに聞く。それ以外は決めて進める。
5. 主の型に、別の型を付録として添えてよい（例：戦略ブリーフ＋付録に香港の質問票）。

### 選定表

| 読み手にしてほしいこと | 型 | テンプレート | 典型的な材料・場面 |
|---|---|---|---|
| レビュー・助言 | **戦略ブリーフ（相談型）** | `templates/strategy-brief.html` | 戦略の整理を有識者に見てもらう |
| 現地・次回会議で確かめる | **戦略ブリーフ（確認型）** | 同上（第4章を確認型に） | 視察前、相手との初回面談前 |
| 判断・決裁 | **戦略ブリーフ（意思決定型）**／短ければ **1ページャー** | 同上／構成のみ（3章） | 経営会議、投資の可否 |
| 構想を固める（新規事業・新サービス） | **PR/FAQ** | `templates/prfaq.html` | アイデア段階、顧客価値が曖昧なとき |
| 決まったことを残す | **決定記録（ADR）** | `templates/adr.html` | 複数回の会議で決定が積み上がる、蒸し返しが多い |
| 会議の内容を共有する | **議事録・論点整理** | 構成のみ（3章） | 会議直後。決定・ToDo・論点 |
| 現地やヒアリングで聞く | **インタビューガイド** | 構成のみ（3章） | 視察、顧客・パートナーへのヒアリング |
| 検証の結果から学ぶ | **検証ログ** | 構成のみ（3章） | PoC、テスト販売、実験の後 |
| 進捗を追う | **定点レポート** | 構成のみ（3章） | 週次・月次の報告 |
| 出資・参画を決める | **投資メモ** | 構成のみ（3章） | 出資、座組、M&Aの検討 |
| 事実を共有する | **ファクトブック** | 構成のみ（3章） | 市場・競合の調査結果 |
| 相手を動かす（社外） | **戦略ブリーフ（提案型）** | strategy-brief（AIの見立てタグを外す） | 相手企業への提案 |

**迷ったときの目安**
- 「何を決めるか」がはっきりしている → 意思決定型か1ページャー。まだ論点を探している → 相談型。
- 顧客や価値がまだ言葉にできていない → PR/FAQ。言葉にはなっていて、勝ち筋を評価したい → 戦略ブリーフ。
- 同じプロジェクトで会議が3回以上ある → 毎回の議事録に加えて、決定記録を1本持つ。
- 結果の数字があり、仮説の当否を書く → 検証ログ。数字の推移を追うだけ → 定点レポート。

## 2. どの型にも付けるもの・選んで付けるもの

| 部品 | 付け方 | クラス |
|---|---|---|
| 1ページ要約（印刷・転送用） | **必ず付ける**。A4で1枚に収める | `details.opwrap#summary`（strategy-brief の7章） |
| スライド表示 | **必ず付く**（共通の部品に入っている）。右下のボタンか、会議で映すときに案内する | 自動（`.viewbar`） |
| 事実／チームの仮説／AIの見立て／未確認のタグ | 社外向け以外は必ず | `tag f/h/v/u` |
| 試算スライダー | **前提が2つ以上不確かな計算**があるときに付ける（回収年数、損益分岐、ユニットエコノミクス、市場規模の推計） | `.calc`（4章） |
| コールアウト | 読み落とせない前提・制約があるとき | `.callout`／`.callout.info` |
| 評価の○△×表、横棒、濃淡表、2軸の図 | 比較・規模・推移・位置づけを見せるとき | strategy-brief の5章 |

## 3. テンプレートのない型の構成

テンプレートは `templates/strategy-brief.html` を土台にし、章立てだけを入れ替える。部品（カード、表、論点カード、タグ）はそのまま使う。

**議事録・論点整理**
1. 表紙（会議名・日時・参加者）と1ページ要約
2. 決まったこと（`.card.key`）／決まっていないこと（2列）
3. ToDo（表：やること／担当／期限）
4. 論点ごとの整理（節ごとに：概要／会話の整理／議論ポイント／重要な発言の引用）
5. 補足調査（発言の裏取り。事実タグと出典）
6. 次回までの確認事項
- 発言は「○○さん」で引用し、要約と引用を混ぜない。

**インタビューガイド（視察・ヒアリング）**
1. 目的と、確かめたい仮説（仮説表の H 番号）
2. 相手の基本情報（事実）
3. 質問リスト（論点カードを使う）：聞きたいこと／なぜ聞くか（仮説番号）／深掘りの質問／答えで変わること
4. 聞き方の注意（聞く順番、言わない方がよいこと、確かめる資料）
5. 記録欄（質問ごとの空欄の表。印刷して手書きできるように）
- 印刷を前提にし、1ページ要約を「当日持っていく1枚」にする。

**検証ログ（実験レポート）**
1. 1ページ要約（仮説ごとの結果：確かめられた／崩れた／未確認）
2. 仮説と指標（表：仮説／指標／合格の基準）
3. やったこと（期間・対象・方法）
4. 結果（数字。横棒や濃淡表）
5. 学びと、仮説の更新（崩れた仮説の代わり）
6. 次の検証

**定点レポート（週次・月次）**
1. KPIタイル（前回比を `.d` に）
2. 前回からの変化（良い変化・悪い変化）
3. リスクと対応
4. 次の打ち手と、決めてほしいこと
- 毎回同じ並びにする。前回の版を残す。

**1ページャー（意思決定メモ）**
- 本文そのものを1ページ要約の大きさで書く：決めてほしいこと／推奨／理由3つ／選択肢の比較（○△×）／リスク／決めないと何が止まるか・期限。
- 第1〜3章は付けない。根拠は付録に出典として並べる。

**投資メモ**
1. 投資テーマ（一文）と推奨（投資する・しない・条件付き）
2. 市場と、なぜいまか
3. 事業モデルとユニットエコノミクス（試算スライダー）
4. チーム・座組・持分
5. リスク（表：リスク／起きたら／打ち手）と撤退基準
6. 条件（金額・時期・役割）と、決める前に確かめること

**ファクトブック（市場・競合調査）**
1. 結論の要約（結論カード）
2. 市場規模（推計は確度ラベルと計算の前提を必ず）
3. プレイヤーの地図（類型×代表例の表、混み具合の評価）
4. 構造の変化（直近3年）
5. 空いている所と、その理由
6. 出典（番号付き）
- 評価は最後の「空いている所」に寄せ、それ以外は事実だけにする。

## 4. 試算スライダーの書き方

```html
<div class="calc" data-const='{"rate":20}'>          <!-- 動かさない定数（任意） -->
  <div class="ttl">試算の名前</div>
  <div class="ctl"><label>前提の名前<small>根拠・いまの値</small></label>
    <input type="range" data-var="fee" min="1000" max="5000" step="100" value="2000" data-fmt="0" data-unit="円">
    <span class="val" data-show="fee"></span></div>
  <div class="res">
    <div class="tile"><div class="l">結果の名前</div>
      <div class="v" data-expr="bud/(fee*mem*1e4/1e8)" data-fmt="1" data-ok="x<=3"></div>
      <div class="d">判定の基準</div></div>
  </div>
  <button type="button" class="reset">前提を元に戻す</button>
</div>
```

- `data-var` の名前を `data-expr` の式で使う。`data-ok` は結果を `x` として「良い」条件を書く（青＝良い、赤＝悪い）。
- 初期値は資料の値にし、出典を `p.src` に書く。範囲（min〜max）は、現実にあり得る幅にする。
- 印刷すると、初期値ではなく、そのとき画面で選んでいる値が出る。配る前に「前提を元に戻す」を押す。

## 5. 作る手順

1. 型を選び、ユーザーに一文で伝える（1章）。
2. テンプレートを作業用フォルダに複製し、`{{ }}` を埋める。要らない節は消し、目次と番号を振り直す。
3. 1ページ要約の欄を確かめる（自動で埋まる元の `id` を付ける）。
4. Playwrightで確認する：1280pxと390pxで横スクロールが出ない／スライド表示で送れる／要約だけ印刷がA4の1枚（`pdfinfo` で Pages: 1）／試算スライダーが動く／コンソールにエラーがない。
5. 社外秘の中身は公開リポジトリに入れない。作業用フォルダに置いてユーザーに送る（strategy-brief の「保存と共有」）。

## 6. テンプレートを直すとき

- 共通の見た目と動きは `assets/` にある（`base.css`、`components.css`、`onepager.js.part`、`components.js.part`）。各テンプレートの本文は `templates/*.body.html`。
- 直したら `python3 .claude/skills/report-formats/build.py` を実行する。全テンプレートと `strategy-brief/template.html` が作り直される。`templates/*.html` を直接直さない。
